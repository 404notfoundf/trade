# Direct Pool 全部正收益窗口分页设计

**状态：** 已完成，2026-10-17
**日期：** 2026-10-17

## 1. 问题

`/direct-pools` 的“正收益窗口”摘要会先从完整历史决策中重建窗口，但渲染时固定只取最新 20 个：

```ts
positiveWindows.slice().sort(...).slice(0, pageSize)
```

用户能够进入某一个窗口查看其中的全部收益决策样本，却不能继续浏览第 21 个及之后的窗口。把全部窗口直接堆到总览会让首页很长，也会与现有报价记录、收益明细的分页方式不一致。

## 2. 目标与范围

### 目标

1. 在当前选定的时间范围和池子筛选内，分页展示全部符合连续性规则的正收益窗口。
2. 每个窗口继续能进入现有 `/direct-pools/window` 页面，查看该窗口内全部已存储的决策样本。
3. 总览继续只保留最新 20 个窗口，避免首页变长；提供明确入口进入完整列表。
4. 所有列表、统计与详情使用同一个 `collectPositiveWindows` 结果，保证窗口数、排序和边界一致。

### 不在本次范围

- 不改变“两次连续正收益打开、两次连续非正收益结束、超过两分钟无有效样本超时结束”的窗口规则。
- 不新建窗口汇总表、不回填历史、不改变决策保留期限。
- 不将正收益窗口解释为可成交机会、实际收益或累计利润。
- 不增加按资产、方向、规模的独立筛选器；先复用已有时间范围和池子筛选。

## 3. 事实与约束

| 项目 | 现状 | 设计约束 |
| --- | --- | --- |
| 窗口算法 | `collectPositiveWindows()` 在应用层按时间和 ID 排序后重建 | 新页面不得复制或改写算法 |
| 数据来源 | `direct_pool_decision`，`pool_id` 迁移完成后才具备完整窗口覆盖 | 覆盖不完整时不展示可能被截断的窗口 |
| 时间范围 | 自定义范围最大 180 天，窗口按开始时间落入 `[from, to)` | 分页参数必须保留原范围 |
| 当前窗口 | 以所选范围的 `to` 作为观察截止点 | 翻页不能因“现在时间”改变已打开窗口的展示边界 |
| 详情样本 | `/direct-pools/window` 已按窗口首末决策 ID 精确查询 | 完整窗口页必须生成完全相同的详情参数 |

“全部”指当前筛选范围内、在可用决策保留期和完整覆盖起点内的全部窗口，不承诺已清理或迁移前缺失的历史。

## 4. 方案比较

### 方案 A：总览取消 20 条限制

将所有窗口直接渲染在 `/direct-pools`。

- 优点：代码改动最少。
- 缺点：首页会随历史增长而变长；报价、状态区和窗口表混在一起，无法使用既有分页体验。

### 方案 B：新增全部窗口分页页（采用）

新增 `/direct-pools/windows`，复用总览已构建的窗口集合，排序后在内存中按每页 20 条切片。

- 优点：不重复窗口算法、不新增表和迁移；总览保持紧凑；与报价记录、收益明细的分页一致。
- 缺点：每次访问仍需读取覆盖起点到查询结束的原始决策来重建窗口。现有总览已经承担该成本，且查询范围被限制为最多 180 天。

### 方案 C：持久化窗口汇总表

每次决策写入时维护窗口状态和汇总行，再直接数据库分页。

- 优点：读取成本更低，可支持更长历史。
- 缺点：需要处理迟到样本、失效估值、保留清理、窗口重开和历史修复，容易产生与现有纯函数不同的窗口边界。

当前需求选择方案 B。若 180 天决策扫描经实测成为瓶颈，再单独设计可重算的窗口汇总表。

## 5. 页面和路由

| 路径 | 用途 | 入口 |
| --- | --- | --- |
| `/direct-pools` | 收益总览，仍显示最近 20 个窗口 | 当前页面 |
| `/direct-pools/windows?range=...&pool=...&page=...` | 当前条件下全部正收益窗口，按页展示 | 总览窗口表标题旁的“查看全部 N 个窗口” |
| `/direct-pools/window?...` | 单一窗口的全部决策样本 | 全部窗口页和总览均可进入 |

`/direct-pools/windows` 的页面顶部提供“返回收益总览”链接，并复用时间范围、池子选择和范围失效提示。它不加入顶层导航，避免把一个列表页误当成独立业务模块。

## 6. 查询、分页与一致性

```mermaid
flowchart LR
  A[direct_pool_decision 原始决策] --> B[按完整覆盖起点到 range.to 查询]
  B --> C[collectPositiveWindows]
  C --> D[按窗口开始时间倒序]
  D --> E[按 range.from <= startAt < range.to 筛选]
  E --> F[总览: 前 20 条]
  E --> G[全部窗口页: page / 20 切片]
  G --> H[/direct-pools/window: 首末决策 ID]
```

实现步骤：

1. 在现有 `renderDirectPoolPage()` 的同一窗口构建分支中，先生成按开始时间倒序的 `orderedWindows`，供总览和完整列表共同使用；不新增第二套查询或窗口算法。
2. `renderDirectPoolPage()` 识别 `/direct-pools/windows`，解析既有 `page` 参数；复用 `parsePageNumber()`。
3. 窗口集合已在内存中完整生成，使用长度和切片判断页边界：
   - `offset = (page - 1) * pageSize`
   - `visible = allWindows.slice(offset, offset + pageSize)`
   - `hasNext = allWindows.length > offset + pageSize`
4. 调用现有 `pagination()`，使上一页、下一页和跳页都保留 `range`、`pool`。
5. 总览标题改为“正收益窗口（最近 20 个）”，并在标题区域显示链接：`查看全部 ${allWindows.length} 个窗口 →`。无窗口或覆盖不完整时不生成该链接。
6. 总览和完整列表共同调用一个窗口行渲染函数，确保窗口详情 URL、字段和文案一致。

超出最后一页时，显示空状态和“返回第 1 页”链接，不把页码静默改写为第 1 页，避免用户误以为仍在请求的页码。

## 7. 展示口径

完整列表沿用总览列：

- 正收益观测区间、末次正收益时间和结束确认时间（UTC+8）；
- 资产、链、池、方向、规模；
- 末次正收益、窗口峰值；
- 正收益观测跨度和正收益样本数；
- “已结束”或“观察中”；
- “全部收益样本”详情链接。

页首必须说明：窗口是重复报价的观察估算；正收益样本才计入峰值、末次收益和样本数；非正样本只用于窗口连续性判断；页面不代表成交、累计利润或可执行性。

## 8. 错误与边界

1. 迁移记录不存在，或请求范围早于完整覆盖起点：显示当前已有的“窗口历史覆盖不完整”说明，不显示任何窗口和分页链接。
2. 池筛选指向已删除或历史池：按该 `pool_id` 查询，沿用现有页面对历史池的显示方式。
3. 详情链接必须带 `window_first_id`、`window_last_id` 和现有的身份参数；不能改回依赖时间戳匹配。
4. 新页面只读取 `direct_pool_decision`，不改变采集、估值、执行或清理逻辑。
5. 若在翻页期间有新样本写入，窗口排序可能自然变化；页面按请求发生时的实时观察数据展示，不承诺跨页快照一致性。

## 10. 验收标准

1. 当当前范围内有 21 个窗口时，总览只显示最新 20 个，并有“查看全部 21 个窗口”入口。
2. 完整列表第 1 页显示最新 20 个，第 2 页显示其余窗口；排序为窗口开始时间倒序，同开始时间按稳定的现有顺序排列。
3. 翻页、跳页、返回总览、进入并返回窗口详情时，时间范围和池筛选保持不变。
4. 总览和完整列表中同一窗口的开始、状态、样本数、峰值和详情链接参数一致。
5. 覆盖不完整时不展示“查看全部”入口和可能截断的窗口。
6. 超出最后页、空筛选和数据库不可用时显示明确状态，不抛出未处理异常。

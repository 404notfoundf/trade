# 机会簇与看板变化片段设计

## 状态

已完成，2026-10-16。本文定义的 Aggregator 机会摘要、5 秒变化片段和展示边界已实现；不改变报价、估值、执行或真实交易的含义。

## 背景

相邻时间的多条正收益报价通常是同一组市场状态的连续更新。把它们当成多次独立机会会制造看板噪声，也会让使用者误判机会次数。

当前系统已经在 `src/observations.ts` 中把同一 `inst_id + chain_index + direction + size_usdt` 的连续正收益报价合并到一条未结束的 `opportunity`：最新报价更新当前收益，`peak_profit_usdt` 保存峰值；连续两次有效但非正的报价才结束窗口。`src/trading/executor.ts` 已通过数据库命名锁和未结束 `trade_cycle` 检查阻止新交易周期并发执行。

因此，本次工作只补足机会簇的可读展示和短时间变化轨迹，不新增另一套交易防重逻辑。新建普通机会时，开始时间直接沿用首条报价观察时间，确保首个样本计入窗口。

## 目标

1. 机会列表将持续的同一机会显示为一条摘要，而不是把连续报价误读为多个机会。
2. 机会详情能显示 5 秒粒度的变化片段，帮助判断机会是否稳定。
3. 保持现有普通机会窗口与 Direct Pool 收益窗口的生命周期和统计口径。
4. 不改变自动执行安全边界；看板聚合绝不作为执行许可或去重依据。

## 非目标

- 不修改利润、估值、滑点、库存或报价新鲜度计算。
- 不改变普通机会的“连续两次非正报价关闭”规则。
- 不改变 Direct Pool 的 120 秒无有效样本断窗规则。
- 不增加新依赖、后台聚合任务、物化表或缓存。
- 不改自动交易锁、`trade_cycle` 状态机或重试策略。

## 术语和分组

### 普通机会簇

普通机会簇等同于现有 `opportunity` 记录。其身份键为：

`inst_id + chain_index + direction + size_usdt`

在当前 Aggregator 路由模型中，这个键已经足以标识一条可执行路径。只有未来同一标的、链、方向与规模会同时产生多条不同的可执行 DEX 路由时，才扩展身份键：

`inst_id + chain_index + route_or_pool_id + direction + size_usdt`

届时必须先让采集器把稳定的 `route_or_pool_id` 写入 `quote_observation` 和 `opportunity`，并完成历史数据迁移；本次不为尚不存在的并行路径提前添加字段。

### Direct Pool 连续窗口

继续使用既有键：

`instrument_id + chain_index + pool_id + direction + size_usdt`

其连续窗口由 `src/trading/direct-pool-windows.ts` 计算，两个有效样本相隔超过 120 秒时结束。不得改为 5 秒，以免正常的采样间隔把同一池的机会拆开。

### 五秒变化片段

五秒片段是普通机会簇的只读展示数据，不是新的 `opportunity`，不参与报表机会次数，也不触发交易。

对某个 `opportunity`，读取其开始时间到最后观察时间（已结束时读取到 `ended_at`）范围内、且身份键相同的 `quote_observation`。按 UTC 的 5 秒固定桶分组：

`bucket_start = floor(observed_at epoch milliseconds / 5000) * 5000`

一个桶输出一条片段，字段为：

| 字段 | 口径 |
| --- | --- |
| 开始时间 | `bucket_start` |
| 结束时间 | `bucket_start + 5 秒`；最后一个未完成桶显示为“进行中” |
| 样本数 | 桶内符合该机会身份键的原始报价数 |
| 当前收益 | 桶内时间最新报价的 `net_profit_after_rebalance_usdt ?? net_profit_usdt` |
| 峰值收益 | 桶内上述收益的最大值 |
| 最低价格影响 | 桶内可解析 `price_impact_percent` 的最小绝对值；没有数据时显示“未知” |
| 最新报价时间 | 桶内最新 `observed_at` |

片段只纳入 `valuation_status='VERIFIED'` 且 `status='OK'` 的报价。无效、阻断或估值未知的报价仍保留在原始观察和风险记录中，但不伪装成机会变化。

## 页面行为

### `/opportunities`

继续每条 `opportunity` 显示一行。现有字段保留，并增加：

- 最后更新时间：关联最新报价的 `observed_at`；
- 持续时间：`COALESCE(ended_at, 当前时间) - opened_at`；
- 样本数：该机会生命周期内符合身份键且有效的原始报价数量。

“当前 / 峰值收益”继续分别来自该机会的最新收益与 `peak_profit_usdt`。这些数值是观察估算，不得表述为实际交易利润或可累计利润。

### `/opportunity?id=<id>`

在既有详情下增加“变化片段（每 5 秒）”表。默认显示全部片段；若页面体积或查询结果超过现有项目约定的安全上限，可采用与机会列表一致的分页方式。每行显示：

- 片段开始和结束时间（UTC+8）；
- 样本数；
- 当前收益；
- 峰值收益；
- 最低价格影响；
- 最新报价时间。

页面必须说明：片段描述同一连续机会内的报价变化，不代表多个可分别成交的机会。

## 数据库与查询约束

本设计不需要数据库迁移。`quote_observation` 已保存身份键、`observed_at`、净收益、价格影响、估值状态和状态；`opportunity` 已保存开始、结束、当前与峰值收益。

实现查询时：

1. 先按 `opportunity.id` 读出其身份键与 `opened_at`、`ended_at`。
2. 用同一身份键过滤 `quote_observation`，时间范围为 `[opened_at, COALESCE(ended_at, UTC_TIMESTAMP(3))]`。
3. 在 SQL 或纯 TypeScript 中按 5 秒固定桶聚合。若在 SQL 聚合，所有 Decimal 字段以字符串读取后再使用 `Decimal` 比较，避免 JavaScript `number` 精度问题。
4. 为避免活跃窗口查询无限增长，详情查询可只展示最近 24 小时的片段，并在页面明确标注截断；只有实际观察到超过该范围的活跃窗口时才加入分页或范围筛选。本次优先不加该限制和新索引。

## 执行边界

自动交易继续使用当前机制：

- `withNamedLock("xaapl_trade_execution", ...)` 确保多进程之间只有一个执行扫描；
- 存在状态不是 `COMPLETE`、`FAILED`、`RECONCILED` 的 `trade_cycle` 时，暂停启动新的自动交易周期；
- 执行前继续重新报价、检查库存、滑点、估值和最小净边际。

不得用“五秒片段”“样本数”或看板上的当前收益替换这些检查。用户手动打开执行后，也只允许现有执行器启动一笔周期。

## 实施顺序

1. 在 `src/dashboard.ts` 为列表和详情查询补充最后更新时间、持续时间与样本数。
2. 在 `src/dashboard.ts` 增加一个小型纯函数或局部查询映射，将详情原始观察按 5 秒桶整理为展示行；不要引入新服务层。
3. 渲染列表的新列和详情片段表，补充“观察估算、非独立机会”的中文说明。
4. 为分桶逻辑添加小型测试，至少覆盖：同一桶多样本、跨桶、空桶、结束窗口、进行中窗口，以及无效样本被排除。
5. 运行现有类型检查和相关测试；确认 `/opportunities`、`/opportunity?id=<id>`、普通机会关闭和交易控制页均正常。

## 验收标准

1. 同一连续普通机会在列表中始终只有一行，显示开始、最后更新、持续时间、样本数、当前收益和峰值收益。
2. 同一机会在详情页按固定 5 秒时间桶展示报价变化；同桶的多条报价不增加机会数量。
3. 不存在有效报价的桶不显示；`VERIFIED/OK` 以外的样本不计入片段指标。
4. 机会、报表与 Direct Pool 窗口数的现有口径不因本改动而变化。
5. 不产生新的迁移，不修改自动交易锁和 `trade_cycle` 状态机。
6. 页面文案明确区分报价观察、机会窗口和实际成交。

## 风险与后续触发条件

- 活跃窗口若持续很久，详情查询会读取较多原始报价；先以真实数据观察，只有确认慢查询后才增加分页、时间范围或索引。
- 并行可执行路由出现后，未加入路由/池标识会错误合并它们；该能力上线时必须先扩展身份键与迁移数据。

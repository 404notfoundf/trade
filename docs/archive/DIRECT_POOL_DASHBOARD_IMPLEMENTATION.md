# Direct Pool 收益看板拆分实现说明

> 用途：交给实现模型按本文改造 Direct Pool Dashboard。本文是已确认需求与实现约束，不是待办清单；本轮只新增本文档，不改 `docs/TODO.md`。

## 1. 目标与边界

将当前拥挤的 `/direct-pools` 拆成三个用途清晰的页面：

1. **收益总览**：按所选时间范围显示观察统计、正收益估算样本和池状态。
2. **报价记录**：查看 DEX Exact-In 报价成功和失败记录及其原始详情。
3. **收益明细**：查看所有 Direct Pool 决策，包括正收益、负收益、拦截和无法估算的记录。

收益窗口与收益总览用于观察报价，不表示真实成交。所有 Direct Pool 结果继续显示 `NOT_EXECUTABLE`；不得把报价估算表述成已实现收益或可成交收益。本文不要求实现交易执行、Redis、后台任务或新的独立前端框架。

## 2. 当前实现基线

- Dashboard 在 `src/dashboard.ts` 的 `startDashboard()` / `renderPage()` 中按 `url.pathname` 分支渲染，目前没有单独的前端路由框架。
- `/direct-pools` 当前展示正收益窗口摘要、注册池、Exact-In 报价分页和可展开的决策历史；逐条样本在收益明细页查看。
- `/direct-pools/quote?id=...` 已提供单条报价详情，包含 raw 数量、状态版本、RPC 耗时、原始响应及可用的收益拆分。
- `direct_pool_quote` 已有 `pool_id`；`direct_pool_decision` 当前没有 `pool_id`，它通过 `selected_quote_id` 外键关联报价，报价删除后该外键会被置空。
- `src/trading/direct-pool-storage.ts` 负责报价与决策入库；写决策的调用点在 `src/trading/direct-pool-collector.ts`。
- `config.yaml` 当前将报价保留 7 天、决策保留 180 天；清理在 `src/main.ts` 执行。旧决策可保留，但其关联原始报价可能已被清理。
- Dashboard 时间显示使用 UTC+8 格式；数据库时间按 UTC 存储/查询，新增时间筛选必须明确转换时区。

实现前重新检查上述文件，因为本文与代码可能因其他提交而有差异。沿用 `renderPage()` 和现有 HTML/CSS 方式完成最小改动，不借此重构整个 Dashboard。

## 3. 页面与导航

### 3.1 全局与模块导航

- Direct Pool 模式下全局导航名称保持 **“收益估算”**。
- 模块内增加三个同级子导航：**收益总览 / 报价记录 / 收益明细**。
- 当前子页面高亮，并给活动链接设置 `aria-current="page"`。
- 三个页面共用时间范围参数；切换子页、翻页、进入报价详情和返回列表时保留适用的筛选参数。

### 3.2 页面路由

| 路径 | 页面 | 内容 |
|---|---|---|
| `/direct-pools` | 收益总览 | 统计卡、正收益窗口摘要、默认收起的池状态 |
| `/direct-pools/quotes` | 报价记录 | Exact-In 成功/失败记录，分页 |
| `/direct-pools/decisions` | 收益明细 | 所有决策记录，分页 |
| `/direct-pools/windows` | 全部正收益窗口 | 当前时间范围、池筛选内的全部窗口，分页 |
| `/direct-pools/quote?id=...` | 报价详情 | 沿用现有 raw 报价诊断页 |
| `/direct-pools/window?...` | 窗口样本 | 同一正收益窗口内的全部决策样本，分页 |

保留 `/direct-pools/quote` 单数路径，避免破坏已存在的详情链接。其返回链接应返回 `/direct-pools/quotes`，并保留报价页码和时间筛选。若代码内还有旧 `/direct-pools` 报价详情链接，改为新列表页路径；不要移除详情页。

### 3.3 时间筛选

- 预设：**最近 5 分钟、最近 1 小时、最近 24 小时、自定义范围**。
- 默认：**最近 1 小时**。
- 自定义时间按 UTC+8 输入和显示；后端查询使用转换后的 UTC 时间。
- 自定义跨度最长 180 天；开始时间必须早于结束时间。无效参数应显示可理解的提示并回退到默认范围，不得拼接到 SQL。
- 推荐 URL 形态：`range=5m|1h|24h|custom`，自定义范围另带 `from`、`to`。字段格式由实现选择，但须固定解释为 UTC+8，并在页面控件中标清时区。
- 范围使用左闭右开 `[from, to)`，避免相邻时间范围重复计数。预设范围的结束时间取页面请求时的当前时间。
- 收益总览卡片和正样本列表使用所选范围。收益明细支持相同的范围筛选；报价记录受 7 天原始报价保留期限制，超过可用数据范围时须明确提示，不改变数据库保留策略。

## 4. 收益总览定义

### 4.1 统计卡

所有统计按当前时间范围计算，展示以下四项：

1. **正收益估算样本数**：净收益大于 0 的有效估算决策行数。
2. **正收益窗口数**：按第 5 节定义的连续窗口数；时间范围早于完整覆盖起点时按第 6 节显示不完整。
3. **正收益率**：`正收益有效估算数 / 有效估算数`。分母为 0 时显示 `—`，不能显示 0%。
4. **单笔最高净收益估算**：范围内有效估算的最大 `net_profit_usdt`，只取最大值，不累加样本收益。

“有效估算”沿用当前收益列表的基本约束：`net_profit_usdt` 有数值且 `valuation_status` 不是 `INVALIDATED_%`。没有净收益数值的失败、拦截或无法估值记录不进有效估算分母。若记录虽被 guardrail 标记为拦截但仍有数值估算，允许作为观察估算样本参与计算；页面仍须显示拦截状态和 `NOT_EXECUTABLE`，不可称为可成交机会。

统计值是重复采样的观察快照，**不代表独立交易次数，也不能相加成累计收益**。卡片和表格使用“估算/观察”措辞。

### 4.2 正收益窗口表

- 只展示当前时间范围内、符合第 5 节连续性规则且具有完整历史覆盖的正收益窗口。
- 总览默认显示最新 20 个，按窗口开始时间倒序，并提供“查看全部 N 个窗口”入口。完整列表每页 20 个，沿用同一窗口集合、时间范围和池筛选；入口将预设范围固化为自定义起止时间，确保翻页时窗口边界不随当前时间移动。历史覆盖不完整时显示提示，不展示可能被截断的窗口。
- 每行至少显示：UTC+8 正收益观测起止时间、结束确认时间、资产/链/池、方向、规模、末次正收益、窗口峰值、正收益观测跨度、正收益样本数和状态。结束确认时间与末次正收益观测时间分开显示。
- 末次净收益、峰值和样本数只统计正收益观测；连续非正样本仅用于确认窗口结束，不计入窗口指标。超时结束时间是窗口规则的边界，不等于持续可交易时间；观测跨度按首末正收益样本时间计算。
- 详情链接到窗口样本页。窗口构建时记录首末决策 ID；样本页以这对边界 ID 和相同资产、链、池、方向、规模精确取回该窗口内的全部决策样本，包括正收益、零/负收益及无法估值记录，并按时间正序分页。正收益样本标记为计入窗口指标，零/负收益只用于连续性判断，其余记录仅供诊断。
- 窗口样本可继续链接报价拆分详情；如果 `selected_quote_id` 已因 7 天清理而为空，显示“原始报价已过保留期”，不要生成失效链接。
- 逐条正收益样本仍可从“收益明细”页按净收益筛选查看；孤立正样本不会出现在窗口表中，但仍计入样本统计。

### 4.3 池状态

- 把已登记池的状态和收益总览放在一起。
- 池状态区域默认收起，展开后使用现有池状态数据展示启用状态、模式、监控/连接状态、报价新鲜度、RPC 核验、池地址等现有信息。
- 不新增池控制、启停 API 或额外池指标。本项仅调整页面信息组织。

## 5. 连续正收益窗口算法

窗口是“同一观察条件下连续出现的正收益估算区间”，不是成交仓位、实际交易或累计利润。

### 5.1 分组键

按以下字段分组，彼此不同的观察条件不得合并：

`instrument_id + chain_index + pool_id + direction + size_usdt`

`pool_id` 为空的历史记录无法可靠归属池，不参与窗口算法，但仍可参与第 4.1 节的样本统计。

### 5.2 有效序列与状态转移

- 只用有数值 `net_profit_usdt` 且估值未被 `INVALIDATED_%` 作废的决策作为有效样本。
- quote 失败、无估值、null 净收益、无池 ID 的记录不能当成亏损样本；无效记录不增加正/非正连续计数。
- 对每个分组按 `created_at ASC, id ASC` 处理有效样本。`net_profit_usdt > 0` 为正样本；`net_profit_usdt <= 0` 为非正样本。
- 无窗口时，连续 2 个正样本确认一个窗口。窗口 `start_at` 记为这两个确认样本中**第一个正样本**的时间，以此定义“窗口开始时间”。
- 窗口打开后，连续 2 个非正样本关闭窗口，`end_at` 记为第二个非正样本的时间。窗口打开期间出现正样本，清空非正连续计数。
- 自最近一个有效样本起超过 2 分钟仍无新的有效样本时，打开中的窗口以 `last_valid_at + 2 分钟` 标记为超时结束；尚未确认的单个正样本也过期清空。下一条有效样本重新开始判断。
- 失败/无效记录本身不关闭窗口，也不算亏损；若它们造成有效样本间隔超过 2 分钟，则由上述无有效样本超时规则结束窗口。
- 同一分组中窗口关闭后，后续正样本可再次开启新窗口。

### 5.3 窗口指标口径

- 统计选定范围内 `start_at ∈ [from, to)` 的窗口数。即使窗口结束时间在范围外，该窗口仍计数。
- 为识别边界附近的连续状态，不能只加载筛选范围内的行。窗口状态应从完整覆盖起点开始，按时间顺序处理到所选范围结束，再按窗口 `start_at` 过滤计数。
- 不计算或显示窗口收益合计；不把连续观察样本包装成可实现的套利次数。

## 6. 数据迁移、保留与历史完整性

### 6.1 `pool_id` 持久化

新增顺序迁移（当前最新迁移为 `014`，实现时使用下一个编号），对 `direct_pool_decision` 增加 nullable `pool_id VARCHAR(128)`，并添加支持时间范围/池分组读取的索引。字段类型与 `direct_pool_quote.pool_id` 保持一致。

回填规则：

```sql
UPDATE direct_pool_decision d
JOIN direct_pool_quote q ON q.id = d.selected_quote_id
SET d.pool_id = q.pool_id
WHERE d.pool_id IS NULL;
```

仅以明确的 `selected_quote_id` 关联回填。不得从 `instrument_id`、链、当前配置池顺序或字符串化 `attempts` 推断池 ID。没有可验证报价关联的旧记录保持 `NULL`。

迁移后，更新 `DirectPoolDecisionRecord`、`saveDirectPoolDecision()` 以及 `src/trading/direct-pool-collector.ts` 的全部写入点：

- observe-only 每池扫描：直接写入当前 `pool.id`。
- 多池候选扫描：被选中的报价明确对应一个池时，决策写入该报价的 `pool_id`；不得只用 `route.pools[0]` 冒充最终选中池。
- 多池扫描未选中报价或无法唯一确定池时，写 `NULL`。若调用路径本身只对应唯一的池，可写该池 ID。
- 报价删除后，外键仍可把 `selected_quote_id` 置空，但已写入决策的 `pool_id` 保留，以便在 180 天决策周期内计算窗口。

实现时检查所有 `saveDirectPoolDecision()` 调用者和每种 scan 路径，避免只更新主要成功路径。

### 6.2 历史窗口统计覆盖

- 决策保留 180 天，报价保留 7 天。保留策略不变。
- 新迁移可为当前仍存在的报价关联决策回填 `pool_id`；超过报价保留期且关联已清除的旧记录无法回填。
- 新增迁移的 `schema_migrations.applied_at` 作为保守的完整窗口覆盖起点：从该时间起，新版本必须为可归属决策直接写 `pool_id`。迁移前的回填行可以用于样本统计，但不能让系统声称迁移前的整个窗口历史完整。
- 若所选范围起点早于覆盖起点，样本数、正收益率、最高样本收益仍按整个所选范围统计；窗口卡片显示 **“数据不完整”**，并说明“完整窗口统计始于 YYYY-MM-DD HH:mm UTC+8”。不要显示一个看似完整的部分窗口数。
- 若范围完全位于覆盖起点之后，显示窗口数。
- 如果迁移/启动流程找不到覆盖时间元数据，按不完整处理，不能默认完整。

覆盖起点是统计可信度边界，不是历史数据删除点。已有数据仍可查询和展示。

### 6.3 兼容和失败行为

- Dashboard 在迁移尚未执行或查询失败时，沿用现有友好错误提示，不能让页面整个 500。
- 部署时先停止旧版 Direct Pool 采集写入进程，再执行 `npm run db:migrate`，然后启动包含 `pool_id` 写入逻辑的新版本。这样 `schema_migrations.applied_at` 到新采集器启动之间不会出现旧版写入的 NULL 池 ID 决策；Dashboard 只读进程可以按现有兼容性安排继续运行。
- 如果部署环境无法停止旧采集器，不能直接把迁移时间当完整覆盖起点；应等新采集器已开始可靠写入 `pool_id` 后记录覆盖起点。
- 不修改 `selected_quote_id` 外键行为或现有保留天数。

## 7. 报价记录与收益明细

### 7.1 报价记录页

- 将当前 Exact-In 报价表移到 `/direct-pools/quotes`，包括成功和失败报价。
- 沿用现有方向、raw 数量展示、状态、净收益估算摘要及报价详情链接。
- 使用现有每页 20 条分页方式；分页参数必须合法化，并保留时间筛选。
- 默认按报价 ID/报价时间倒序。详情页返回到报价记录对应页。
- 原始响应仅在现有详情页展示；不得把大段 raw JSON 塞进列表行。
- 页面注明报价保留 7 天，历史决策可能仍存在而 raw 报价已经过期。

### 7.2 收益明细页

- 将当前展开式决策历史改为独立 `/direct-pools/decisions` 页面。
- 展示所有状态：正、负、零收益、拦截、估值失效、无法估算；不可只留下正收益行。
- 默认按 `created_at DESC, id DESC`，每页 20 条，支持上一页/下一页。
- 至少包含 UTC+8 时间、资产/链/池、方向、规模、CEX VWAP、毛收益、CEX 手续费、Gas 预算、净收益/ROI、决策结论、估值状态、执行资格和详情入口。
- 所有行继续标注 Direct Pool 仅观察、`NOT_EXECUTABLE`；无净收益值显示“未估算”，失效估值显示“估值失效”。
- 决策原始行保留 180 天。关联报价已过期时，决策数据仍可展示，报价详情入口显示不可用原因。

## 8. 页面状态、链接和安全要求

- 统一保留时间筛选的 URL 参数；分页只改变对应页码，不清空时间范围。
- 页码只接受正安全整数；非法页码回退到 1。
- 所有用户输入日期先解析、校验并转成 Date/UTC 参数；SQL 时间值使用预编译参数。禁止直接把 query string 拼进 SQL。
- 数据库断开、迁移未执行、空结果、无效自定义时间、越过 7 天报价保留范围及报价已删除均应有明确空状态/提示。
- 所有动态内容继续经过 `escapeHtml()`；新增链接的参数编码沿用 `URLSearchParams` / `encodeURIComponent`。
- 用语中区分“观察估算”“报价记录”“窗口”和“实际成交”。界面不得出现累计实际利润的暗示。
- 控件须有可读标签、键盘可操作和焦点状态；小屏表格沿用现有横向滚动模式。

## 9. 建议实现顺序与文件触点

1. **数据库与采集写入**：新迁移、`src/trading/direct-pool-storage.ts`、`src/trading/direct-pool-collector.ts`。先确保新决策稳定保存池 ID，旧记录安全回填。
2. **窗口计算**：实现尽量小的纯逻辑函数，输入按时间排序的决策样本，输出窗口及覆盖状态。把分组与状态转移写成单元测试，覆盖第 10 节场景。除非 180 天读取的实测性能不可接受，不先加窗口汇总表/后台物化任务。
3. **Dashboard 查询与路由**：`src/dashboard.ts` 的类型、路径分支、时间范围解析、查询、链接和分页。
4. **视觉结构**：模块子导航、四项统计卡、正样本表、默认收起池状态、独立报价和决策表。
5. **核对**：执行迁移；运行相关单元测试及项目已有 build 命令；浏览三个页面、报价详情返回、分页和 UTC+8 自定义范围。

实现时不要把不同页面抽成新的 SPA/服务，也不要借机改采集频率或盈利公式。只有 180 天窗口读取经实际测量过慢时，才提交独立的性能方案。

## 10. 验收标准

### 统计与窗口

- 默认打开收益总览时选择最近 1 小时；5 分钟、24 小时和自定义范围能正确切换，UI 按 UTC+8 显示。
- 正收益数、有效估算分母、正收益率、单笔最高值只覆盖 `[from, to)`，并正确排除 null 和 `INVALIDATED_%` 估值。
- 单笔收益不会相加；同一连续窗口内多条正样本不会被显示成多次累计收益。
- 连续 2 个正样本恰好开启一个窗口，start 为第一个正样本时间；连续 2 个 `<= 0` 样本关闭窗口，end 为第二个非正样本时间。
- 一个非正样本打断待确认正样本；窗口打开后的一个正样本重置待关闭计数。
- 失败/null/估值失效样本不作为亏损；超过 2 分钟无有效样本时打开窗口超时，待确认单个正样本也不跨过超时继续凑数。
- 不同池、方向或规模的样本不会合并。
- 统计所选范围的窗口时，能够正确排除在范围前开启但在范围内仍打开的窗口；范围内开启、范围外关闭的窗口仍计数。
- 时间范围跨越覆盖起点时，样本统计仍完整按选定范围算；窗口卡显示不完整和 UTC+8 覆盖日期，不伪装成完整数量。

### 数据与页面

- 迁移在全新数据库和已有 014 数据库上均可执行；有报价外键的可回填，已丢失关联的历史行保持 `pool_id=NULL`。

- 报价删除后，决策的 `pool_id` 仍存在，quote 外键仍可为 NULL。
